- Customer and intended impression: the demo is a considered, approachable local studio.
- Visual direction: warm neutral surfaces, dark text, serif headings, straightforward body copy and restrained geometric decoration. Replace this deliberately for the actual business.
- Typography and assets: the demo uses system font stacks and CSS shapes; no client asset rights have been established. Record selected font/image licenses in BRAND.md.
- Layout: a readable content shell, opening offer/action, service cards, process, disclosures and contact section. Phone layouts stack the content. The breakpoint is defined in tokens.css and global.css; native media queries use literal conditions.
- Component usage: ActionLink is a navigation link, not a submit button. ServiceCard holds one service. Disclosure uses native details/summary. Header, footer and Hero are shared by the actual page and review examples.
- Blog: shared heading/body roles and a narrower reading width; preserve readable paragraphs and links.
- Interaction: use visible keyboard focus and reduced-motion behavior. Form states are designed and verified when a real form is added.
- Review: run the local site and open `/design/` plus the real homepage/blog. Internal examples are excluded from production output. Record the reviewed version/date and unresolved issues below.
